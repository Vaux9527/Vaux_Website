MiniSec

Web 安全漏洞教学靶场

Web Vulnerability Teaching Lab

MiniSec 是一个面向网络安全学习者的 Web 漏洞教学靶场：覆盖 6 类漏洞共 10 个关卡，每一关都走完「原理 → 操作 → 分析 → 成因 → 修复」五段。SQL 真的执行、脚本真的在浏览器里弹窗、命令真的在系统上跑、上传的文件真的落盘——目标不是「看懂」，而是「亲手做过一遍」。

它最坚持的一条设计是 通关判定看事实，不看关键词：判的是查询实际返回了几行、提交的凭据是不是一组合法凭据、结果里有没有内部表的数据、磁盘上那个文件的文件头是不是图片、目标地址解析出来是不是内网 IP——所以用黑名单之外的手法绕过时，判定依然正确，每一条判定标准也都能写进文档、可以复现。

平台自身与靶子刻意分家：靶子注定会被打穿，因此一关一个独立靶子库（6 个库 + 2 个靶子目录），与平台账号数据完全隔离，还可以一关一关地单独恢复出厂。平台自己的代码全程参数化查询、密码哈希存储、CSRF 令牌校验、每 IP 限速。

2026 年 9 月 19 日，全部 10 个关卡完成，配套 166 项自动化回归测试与逐关验收脚本（每关跑一个正例 + 一个反例，证明判定既不过松也不过严），MiniSec 正式结项。靶场只在本机运行、不上线——也正因为如此，命令注入那一关才敢做成真的执行系统命令（工作目录固定在沙箱、3 秒超时、输出截断）。

关卡覆盖

Levels — 6 Vulnerability Classes, 10 Levels

  • SQL 注入（3 关）基础查询注入 · 登录绕过 · UNION 跨表读取
  • XSS（2 关）反射型（不做过滤，先看清最基本的因果关系）· 存储型（弱黑名单绕过 + 持久化影响面）
  • 文件上传只做后缀黑名单的校验为什么靠不住，以及「上传目录能被浏览器直接访问」的后果
  • SSRF服务端请求伪造：让服务器去访问它内部才够得着的地方
  • 命令注入字符串拼接 + 交给 shell，两个条件缺一不可
  • 越权访问（IDOR）认证不等于授权：身份不变，改一个编号就读到别人的数据
  • CSRFCookie 只证明「你是谁」，不证明「这个请求是你发的」

MISC Hunter

CTF MISC 自动化分析工具

Automated CTF MISC Analysis Engine

MISC Hunter 是一个模块化的 CTF MISC 分析引擎：输入一个可疑文件，引擎会自动识别文件类型、执行常见分析、发现异常特征，再调用对应插件提取隐藏数据，并把每个新产物重新送入分析队列继续递归，直到没有新的发现，最终输出日志、报告与提取链。

它的设计哲学很朴素——「机械自动化，推理留人类」：找到 flag 就直接报告；找不到就把文件、字符串与解码候选清晰地呈现出来；分析不出来的则明确列入「待人工分析」清单，绝不悄悄消失。从 v1.0 到 v3.0，工具覆盖面不断加深，核心依然保持纯 Python 实现、零强制第三方依赖，Kali Linux 与 Windows 均可运行。

2026 年 9 月 7 日，v4.0 发布——搭载 DeepSeek 的 AI 辅助层（--ask / --rank / --agent 三种只读模式）随之落地，MISC Hunter 四代版本全部完成并正式结项：从 v1.0 一条能跑的流水线，成长为「确定性分析 + 人机接力 + AI 建议」的完整 MISC 分析体系。

核心能力

Capabilities

  • 全流程自动化：类型识别 → 隐写检测 → 数据提取 → 递归分析，结果汇总为报告与提取链
  • 插件自动发现：一个插件只解决一个问题，按 priority 自动编排，扩展插件无需改动主程序
  • 异常隔离与降级：单个插件崩溃不影响整体分析，外部工具缺失时自动提示并跳过
  • 人机接力：自动解密失败时通过 DECRYPT_NEEDED 把线索交给人类，支持目录批量分析与递归护栏
  • 密钥解密框架：XOR → Serpent → AES/DES/3DES 组合尝试，命中即报告完整解密路径
  • 候选不丢弃：无法唯一判定的爆破候选全部落盘，交由字符串匹配与人工最终裁决
  • AI 只读辅助（v4.0）：--ask 解释 / --rank 候选裁决 / --agent 研究建议，AI 只提供建议、从不参与最终裁决
